This is a fundamental pipeline architecture decision with real tradeoffs. Here is the honest analysis.

---

## The core tradeoff

You are choosing between two designs:

**Materialized pipeline** — run each stage, save output to disk, next stage reads from disk.
```
raw .npy → [normalize] → normalized.npy → [color convert] → lab_hed.npy → [features] → features.npy
```

**Streaming pipeline** — process each image fully through all stages in one pass, never save intermediate results.
```
raw .npy → [normalize → color convert → extract features → sample pixels] → X.npy, y.npy
```

Only the final training matrix `X` and `y` get saved. Everything in between is computed in RAM and discarded.

---

## Why streaming is the right choice for your situation

**Disk math.** PanNuke has ~7,904 images at 256×256×3 float32. One stage of processed data is roughly `7904 × 256 × 256 × 3 × 4 bytes ≈ 6.2 GB`. You have already done 3 stages (normalized, LAB, HED, HSD). If you materialized all of them that is already ~25 GB of intermediate data. Feature maps at 91 features per pixel would be `7904 × 65536 × 91 × 4 bytes ≈ 190 GB`. That is not feasible on any normal machine.

**The intermediate stages have no standalone value.** You will never load the normalized images for any purpose other than extracting features from them. You will never load the LAB images for any purpose other than computing color statistics from them. There is no reason to persist them.

**Your existing streaming loader already supports this.** Your `streaming_loader.py` was designed for exactly this — it processes in batches without writing intermediate features to disk. The notebook inspection you have done is sufficient to validate each stage. You do not need the full dataset on disk to have confidence the stages are correct.

**The final outputs are small.** After sampling (400 pixels per class per image), your training matrix is roughly `7904 × 400 × 3 classes × 91 features × 4 bytes ≈ 3.5 GB`. That is the only thing worth saving.

### Step 2 — Build the streaming feature extraction function

This is the key function. It takes a raw image and its mask and returns sampled pixel features and labels in one shot:

```python
def process_one_image(image_raw, mask, normalizer, label_mode='binary',
                       n_per_class=400):
    """
    Full pipeline for one image: stages 1-3-4-5 in memory.
    Nothing is written to disk except the returned arrays.
    """
    # Stage 1-2: normalize + color convert (in memory)
    img_norm = normalizer.transform(image_raw)   # uint8
    spaces   = convert_image(img_norm)           # dict of float32 arrays

    # Stage 3: generate labels (in memory)
    if label_mode == 'binary':
        labels = generate_binary_labels(mask)
    else:
        labels = generate_3class_labels(mask)

    # Stage 4: extract features (in memory, discarded after sampling)
    features = extract_all_features(img_norm, spaces)  # (65536, 91)

    # Stage 5: sample pixels (keeps only ~1200 rows out of 65536)
    indices, sampled_labels = active_boundary_mining(
        labels, n_per_class=n_per_class
    )

    return features[indices], sampled_labels   # (~1200, 91) and (~1200,)
```

The key line is `features[indices]` — you compute the full 65,536-row feature matrix but immediately index into it to keep only ~1,200 rows, then the 65,536-row matrix goes out of scope and is garbage collected. Peak RAM usage is one image worth of feature maps at a time, which is `256 × 256 × 91 × 4 bytes ≈ 24 MB`. Completely manageable.

### Step 3 — Accumulate into final training matrix in batches

```python
def build_full_dataset(fold_dirs, normalizer, label_mode, n_per_class=400):
    X_chunks, y_chunks = [], []

    for images_path, masks_path in fold_dirs:
        images = np.load(images_path, mmap_mode='r')  # memory-mapped
        masks  = np.load(masks_path,  mmap_mode='r')  # memory-mapped

        for i in range(len(images)):
            X_i, y_i = process_one_image(
                images[i], masks[i], normalizer, label_mode, n_per_class
            )
            X_chunks.append(X_i)
            y_chunks.append(y_i)

            if (i + 1) % 100 == 0:
                print(f"  {i+1}/{len(images)} — "
                      f"accumulated {sum(len(x) for x in X_chunks):,} pixels")

    X = np.concatenate(X_chunks, axis=0).astype(np.float32)
    y = np.concatenate(y_chunks, axis=0).astype(np.uint8)
    return X, y
```

`mmap_mode='r'` on the numpy loads is important — it memory-maps the `.npy` files rather than loading them all into RAM at once. Each `images[i]` call loads only one image off disk.

### Step 4 — Save only the final matrices

```python
# Run once per experiment, takes ~2-4 hours for full dataset
X, y = build_full_dataset(fold_dirs, normalizer, label_mode='binary')
np.save('data/processed/X_stage1_binary.npy', X)

```

This is the only output that persists to disk. Stages 1–4 are transparent.
