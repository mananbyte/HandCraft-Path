Good question to resolve before running — a memory blow-up mid-training at image 4,000 out of 7,904 is painful. Let me give you the exact numbers and then the strategies.

---

## Step 1 — Calculate actual RAM at every moment

Work through it image by image. At any point in the streaming loop, RAM holds:

**Fixed overhead (loaded once, stays for entire run)**

| Object | Size | Notes |
|---|---|---|
| Python + libraries | ~300 MB | NumPy, skimage, scipy, etc. |
| Fitted normalizer | ~5 MB | staintools stain matrix |
| images.npy mmap handle | ~0 MB | mmap — OS pages in on demand, does not load full file |
| masks.npy mmap handle | ~0 MB | same |

**Per-image peak (exists only while processing image i, then freed)**

| Object | Calculation | Size |
|---|---|---|
| Raw image `images[i]` | 256×256×3×4 bytes (float32) | 0.75 MB |
| Normalized image uint8 | 256×256×3×1 byte | 0.19 MB |
| `spaces` dict (LAB+HSV+HED+HSD) | 4 color spaces × 256×256×3×4 | 3.0 MB |
| Dense feature map | 256×256×91×4 bytes | **23.9 MB** |
| Sampled subset (1,200 rows) | 1200×91×4 bytes | 0.44 MB |

Peak RAM per image = ~28 MB. After `features[indices]` and the image loop advances, everything except the 0.44 MB sampled subset is garbage collected.

**Accumulated training matrix (grows linearly across all images)**

This is the part that actually matters. You keep appending sampled arrays to `X_chunks`:

| Fold | Images | Pixels per image | Accumulation at end |
|---|---|---|---|
| Fold 1 | ~2,656 | 1,200 (400×3 classes) | 2656×1200×91×4 = **1.16 GB** |
| Fold 1+2 | ~5,270 | 1,200 | 5270×1200×91×4 = **2.31 GB** |

So at the point you call `np.concatenate(X_chunks)`, Python holds both the list of chunks (~2.3 GB) AND the concatenated array (~2.3 GB) simultaneously in RAM. That is a **4.6 GB peak** at the very end.

**Total peak RAM profile (full Fold 1+2 run):**

```
Fixed overhead:         ~300 MB
Per-image peak:          ~28 MB
Accumulated X_chunks:  ~2,310 MB  (at last image)
np.concatenate peak:   ~2,310 MB  (brief, during final concat)
─────────────────────────────────
Total peak:            ~4,950 MB  ≈ 5 GB
```

On a machine with 16 GB RAM, this is fine. On 8 GB, it is tight but manageable if you handle the concatenation step carefully. On 4 GB, it will OOM at the concatenation step.

---

## Step 2 — The one real danger: the concatenation double-peak

The dangerous line is:

```python
X = np.concatenate(X_chunks, axis=0)  # holds both X_chunks AND X simultaneously
```

At this moment RAM spikes to 2× the accumulated size. Here are two ways to eliminate this:

**Option A — Write directly to a pre-allocated memmap (recommended)**

Pre-allocate the output array on disk as a memory-mapped file. Each image's samples are written directly into the right rows. No list accumulation, no final concatenation, no double-peak. Peak RAM stays at ~330 MB for the entire run.

```python
import numpy as np
import os

def build_dataset_memmap(fold_dirs, normalizer, label_mode,
                          output_X_path, output_y_path,
                          n_per_class=400):
    """
    Streams all images and writes sampled features directly to
    a memory-mapped file. Peak RAM = ~330 MB regardless of dataset size.
    """
    # --- Pass 1: count total samples so we can pre-allocate ---
    print("Pass 1: counting samples...")
    total_samples = 0
    n_classes = 2 if label_mode == 'binary' else 3

    for images_path, masks_path in fold_dirs:
        images = np.load(images_path, mmap_mode='r')
        masks  = np.load(masks_path,  mmap_mode='r')
        for i in range(len(images)):
            # Count unique classes in this mask
            if label_mode == 'binary':
                labels = generate_binary_labels(masks[i])
            else:
                labels = generate_3class_labels(masks[i])
            for cls in range(n_classes):
                total_samples += min(n_per_class, (labels == cls).sum())

    print(f"Total samples across dataset: {total_samples:,}")

    # --- Pre-allocate output files on disk ---
    N_FEATURES = 91
    X_mm = np.lib.format.open_memmap(
        output_X_path, mode='w+', dtype=np.float32,
        shape=(total_samples, N_FEATURES)
    )
    y_mm = np.lib.format.open_memmap(
        output_y_path, mode='w+', dtype=np.uint8,
        shape=(total_samples,)
    )

    print(f"Pre-allocated X: {X_mm.nbytes / 1e9:.2f} GB on disk")

    # --- Pass 2: stream and write ---
    print("Pass 2: extracting features...")
    write_ptr = 0   # current write position in memmap

    for images_path, masks_path in fold_dirs:
        images = np.load(images_path, mmap_mode='r')
        masks  = np.load(masks_path,  mmap_mode='r')

        for i in range(len(images)):
            # Full pipeline in memory — peak ~28 MB here
            img_norm = normalizer.transform(images[i])
            spaces   = convert_image(img_norm)

            if label_mode == 'binary':
                labels = generate_binary_labels(masks[i])
            else:
                labels = generate_3class_labels(masks[i])

            features = extract_all_features(img_norm, spaces)  # (65536, 91)
            indices, sampled_labels = active_boundary_mining(
                labels, n_per_class=n_per_class
            )

            n_sampled = len(indices)

            # Write directly to disk — no RAM accumulation
            X_mm[write_ptr : write_ptr + n_sampled] = features[indices]
            y_mm[write_ptr : write_ptr + n_sampled] = sampled_labels

            write_ptr += n_sampled

            # Explicitly free large intermediate objects
            del features, spaces, img_norm
            # Python GC will collect but explicit del is safer in tight loops

            if (i + 1) % 200 == 0:
                print(f"  [{i+1}/{len(images)}] written {write_ptr:,} rows — "
                      f"RAM: check with htop")

    # Flush memmap to disk
    X_mm.flush()
    y_mm.flush()

    print(f"\nDone. Final shape: X={X_mm.shape}, y={y_mm.shape}")
    print(f"Written to: {output_X_path}, {output_y_path}")
    return X_mm, y_mm
```

Pass 1 counts total samples so you know the exact pre-allocation size. Pass 2 writes directly. The RAM profile stays flat at ~330 MB throughout the entire run, no matter how large the dataset is.

**Option B — Chunk-flush accumulation (simpler, if you have 8 GB+ RAM)**

If you prefer the simpler list-accumulation approach but want to avoid the double-peak, flush to disk every N images and reload:

```python
FLUSH_EVERY = 500   # images

X_chunks, y_chunks = [], []
chunk_idx = 0

for i, (img, mask) in enumerate(image_iterator):
    X_i, y_i = process_one_image(img, mask, normalizer, label_mode)
    X_chunks.append(X_i)
    y_chunks.append(y_i)

    # Flush every FLUSH_EVERY images to avoid double-peak
    if (i + 1) % FLUSH_EVERY == 0:
        chunk_path = f"data/processed/chunk_{chunk_idx}.npy"
        np.save(chunk_path, np.concatenate(X_chunks, axis=0))
        np.save(chunk_path.replace('chunk_', 'y_chunk_'),
                np.concatenate(y_chunks, axis=0))
        X_chunks.clear()
        y_chunks.clear()
        chunk_idx += 1
        print(f"Flushed chunk {chunk_idx}")

# At the end: merge chunks on disk (low RAM cost — reads one chunk at a time)
# Then delete temporary chunk files
```

This keeps peak RAM during any single flush to `500 × 1200 × 91 × 4 bytes ≈ 220 MB`, well within any machine.

## Step 3 — Monitor RAM while running

Before starting a full run, add a RAM monitor so you can see if something is leaking:

```python
import psutil, os

def log_ram(label=""):
    proc = psutil.Process(os.getpid())
    ram_mb = proc.memory_info().rss / 1e6
    print(f"[RAM] {label}: {ram_mb:.0f} MB")

# Call this every 100 images inside the loop
if (i + 1) % 100 == 0:
    log_ram(f"image {i+1}")
```

If RAM grows linearly without ever dropping back, you have a reference leak — some intermediate object is being held accidentally. The most common cause is keeping a reference to `spaces` or `features` outside the loop scope without explicit `del`.

## Step 4 — The GLCM special case

If you add GLCM features to the pixel extractor (which computes a 32-level GLCM per sampled pixel's neighborhood), this runs *after* sampling, so it never builds a dense feature map. But each GLCM computation allocates a small temporary array. With 1,200 sampled pixels per image and 7,904 images, that is ~9.5 million GLCM calls. Python's garbage collector handles this fine but you may see RAM creep upward slowly. If you do, call `import gc; gc.collect()` every 100 images.

---

## Practical recommendation

Use **Option A (memmap)** if you have any concern about RAM. It is the more robust solution — peak RAM is predictable and constant regardless of dataset size, and the output file is ready to use immediately without a separate concatenation step. The two-pass design (count then write) adds maybe 10 minutes to a full run but eliminates all memory risk.

Use **Option B (chunk-flush)** if your machine has 16+ GB RAM and you want simpler code to debug. Each chunk flush takes ~1 second and the final merge is straightforward.

Either way, `mmap_mode='r'` on the raw numpy loads is non-negotiable — without it, loading `images.npy` for Fold 1 alone (~6 GB) will consume your RAM before you process a single image.
